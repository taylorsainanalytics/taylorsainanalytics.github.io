01 · THE BUSINESS PROBLEM

Generative AI needed structured inputs. The source content was trapped in PDFs.

The downstream AI process depended on high-quality source content, but the required information lived inside consistently designed yet still unstructured PDF pages.

The existing approach required people to locate two target content blocks, copy the text, capture contextual metadata, and manually place each result into an Excel model. The documented baseline was approximately 3 hours for 180 content blocks, with an initial automation target of roughly 750 units.

The problem was therefore not simply “extract text.” The output had to preserve the right content, metadata, structure, and consistency so it could be trusted downstream.

LAYOUT-AWARE EXTRACTION

The PDF was treated as a visual document, not a text blob

Different page designs placed target content in different regions. I used coordinate-based extraction areas and separate handling for layout variants rather than scraping every word on the page.

BUSINESS RULES

Stopping rules protected output quality

The scripts stopped or skipped content when known section markers appeared, preventing neighboring material, support text, production artifacts, and unrelated sections from contaminating the output.

METADATA PARSING

Context traveled with the extracted content

Standardized filename patterns were parsed into reporting dimensions such as module, week, lesson, and page identifiers so each extracted block retained the context needed downstream.

STRUCTURED OUTPUT

The deliverable was data, not another document

Extracted content was written into a consistent Excel schema, turning unstructured page content into rows that could be reviewed, manipulated, and passed into the AI workflow.

def text_blocks(page, region):
    blocks = page.get_text("blocks", clip=region)
    visible = [
        (block[4], block[:4])
        for block in blocks
        if "<image:" not in block[4]
    ]
    return sorted(visible, key=lambda block: block[1][1])


def extract_objectives(page):
    objectives = []
    for text, _coords in text_blocks(page, CONTENT_REGION):
        cleaned = text.strip()
        if cleaned.upper().startswith("MATERIALS"):
            break
        if cleaned:
            objectives.append(cleaned)
    return "\n".join(objectives)

HOW I BUILT IT

The extraction logic evolved through testing, not assumptions.

  1. Mapped the manual process.Defined the exact content blocks, contextual fields, expected output structure, and manual effort being replaced.
  2. Analyzed the documents.Studied page layouts and recurring markers to determine which regions and rules could reliably locate the required content.
  3. Built extraction variants.Developed Python logic for differing layouts, page orientations, and content patterns rather than forcing one parser across every document.
  4. Structured the data.Combined extracted text with parsed document metadata and wrote the output into the required Excel schema.
  5. Tested against expected output.Ran smaller samples first, compared results to the existing model, debugged anomalies, then executed the full-scale extraction.
  6. Delivered an AI-ready dataset.Produced a consistent, quality-assured structured file ready for use by the downstream generative AI process.

LESSON LEARNED

AI readiness starts long before the model.

The most important part of this project was not the AI itself. It was creating reliable inputs.

Automating document extraction required understanding the source layout, defining what “correct” meant, encoding exceptions, structuring metadata, and validating the result. That data-preparation layer is what made the downstream AI workflow practical at scale.
